## 1.6.0 (2026-11-21)

Template 1.6.0, companion plugin `plg_system_bsbasicog` 1.2.0.

### Feature: Bootstrap options for front-end developers (2026-11-21, branch feat/bootstrap-options)
First step toward making the template friendlier to developers who know Bootstrap. Every new param reproduces the previous output at its default (checked by diffing four test-site pages before and after). Joomla's precompiled `bootstrap.min.css` stays the only Bootstrap, so everything works through `--bs-*` variables, classes and `data-bs-*` attributes.
- New **Bootstrap** tab. Extra Classes adds your own classes to eight wrappers (body, header, navbar, main area, main column, sidebars, bottom row, footer). Bootstrap JS Components loads Joomla's bundled alert, carousel, dropdown, modal, offcanvas, popover, scrollspy, tab, toast and tooltip scripts on demand; tooltip, popover and toast are also initialized. Load Font Awesome uses Joomla's bundled copy. Breakpoint Indicator shows the current breakpoint while System Debug is on.
- Appearance › **Bootstrap Theme Colors**: Secondary, Success, Info, Warning, Danger, Light and Dark. Each sets the full `--bs-{color}` set and the button, `.text-bg-*` and `.link-*` rules Bootstrap hard-codes, using Bootstrap's own shade and contrast rules.
- Header & Footer › Menu: **Menu Alignment** (end/center/start), **Menu Style** (Template/Pills/Underline), **Mobile Menu** (Collapse or Offcanvas from either side).
- Bootstrap › **Tables & List Groups**: Tables follow Theme Colors (default No) recolors `.table-*` from the palette with Bootstrap's own table math. List Groups follow Theme Colors (default Yes) keeps `.list-group-item-*` on the palette, adds Light/Dark, and No restores Bootstrap's own list-group colors.
- Per-page Bootstrap JS: the companion plugin `plg_system_bsbasicog` adds a **Bootstrap** tab to site menu items with the same component checkboxes. The template loads the style's components on every page plus the active menu item's on that page (and pages opened from it), only while the plugin is enabled.
- Layout: **Boxed From** (responsive `container-{bp}`), **Sidebar Breakpoint** (md/lg/xl), **Content First on Small Screens** (`order-*`) and **Grid Gutter** (`gx-*`/`g-*`).

### Fix: Bootstrap's `*-primary` utilities follow the site's primary color (2026-11-21, branch feat/bootstrap-options)
Only `--bs-primary` was set, not `--bs-primary-rgb` and the subtle/emphasis variants. So `.text-primary`, `.text-bg-primary`, `.border-primary`, `.link-primary` and `.alert-primary` stayed Bootstrap blue, and `.bg-primary` needed an inline patch. The full primary set is now static in `_base.scss` for the default accent, and emitted from `index.php` when a Primary or Accent Color is set. The `.bg-primary` patch is gone. Visible change: those utilities now turn red (or the chosen primary) on existing sites.

## 1.5.0 (2026-11-19)

### Feature: article dates in Open Graph and schema.org (2026-11-19, branch feat/article-dates)
Found while building a site search: article pages had no machine-readable publish or modified date. Joomla's automatic schema.org `Article` node only has `dateCreated` (and only with Show Publish Date on) plus `dateModified` with Show Modify Date on, and the Schemaorg - BlogPosting dates are typed by hand per article. The companion plugin `plg_system_bsbasicog` now, on article pages:
- sets `og:type` to `article` (the template's default stays `website` elsewhere) and adds `article:published_time` and `article:modified_time`;
- listens to `onSchemaBeforeCompileHead` (priority LOW) and adds `datePublished` and `dateModified` to the article's JSON-LD node (`#/schema/com_content/article/<id>`), whether core's automatic `Article` or a type from the article's Schema tab; dates an editor entered there are kept.
Dates: Start Publishing, else Created; Modified, else the published date; ISO 8601 UTC; output regardless of the article's Show Publish/Modify Date settings. The article row is loaded once per request (attribs and dates in one query). Checked on a test site with Joomla sample data: article pages get both outputs, home and blog pages keep `og:type` `website`. Not checked: an article with a BlogPosting type set in its Schema tab.

## 1.4.1 (2026-11-19)

### Fix: `<main>` holds only the component; sidebars are `<aside>` (2026-11-19)
Found while building a site search: `<main class="bsbasic-main">` wrapped the system messages, breadcrumbs, main-top/main-bottom modules and both sidebars, so crawlers and screen readers took sidebar menus and module text as page content. `.bsbasic-main` is now a `<div>`; `<jdoc:include type="component" />` sits alone in `<main class="bsbasic-content">` (the system message box stays where it was, above the breadcrumbs and outside `<main>`), and each sidebar's `.bsbasic-sidebar` wrapper is an `<aside>` labelled "Left sidebar" / "Right sidebar" (new keys `TPL_BSBASIC_SIDEBAR_LEFT`/`_RIGHT`). Class names are unchanged, so layout and styles are unaffected; `_layout.scss` now targets `.bsbasic-main` instead of `main.bsbasic-main`. Sites with a `css/user.css` or Custom CSS that targets the `main` element need updating. Not yet checked live.

### Fix: collapsible sidebar opened the wrong branch (2026-11-12)
On a real-world test site's `/blog` the sidebar menu opened 2023 instead of 2026. The 2023 item is a menu alias to Blog, and core marks an alias of the current page `active`; `js/sidebar-menu.js` opened every `parent.active`. It now opens a parent only when it is, or contains, the `current` item. Pages with no menu item of their own start fully collapsed. Needs a repackaged template on sites that install from the zip. Not yet checked live.

## 1.4.0 (2026-11-12)

The first entries below were first built as 1.4.0; the later ones (blog items, slider, on-load fix, footer) were folded into 1.4.0 because the version had not left the local machine.

### Animation: blog items (2026-11-12, branch feat/blog-item-animation)
Category and blog listing items (`.blog-items > .blog-item`, the wrapper around `.item-content`) now take part in the entrance animation as cards: `.blog-items > .blog-item` was added to the card selector in `js/animate.js` (core `com_content` markup, so a selector rather than the `bsbasic-reveal` class). New **Blog Items** param (`animBlog`, Appearance > Animation): Entrance only (default) or Entrance and hover. Entrance and hover puts `bsbasic-blog-hover` on `<body>`; `scss/_animations.scss` then applies the Tile Hover Effect to blog items: Lift only on Boxed layouts (`.blog-items.boxed`), where an item is a bordered card, and Zoom on any item's intro image (`.item-image img`). Plain list items get no lift because they are rows with a bottom rule. The item transition is wrapped in `:where()` so the entrance transition still wins on specificity. Stagger cap unchanged (8 steps). Manifest and both language files updated. Not yet checked live.

### Fix: cards written into an article body now animate (2026-11-12)
Found on a test site: three plain `<div class="card h-100">` cards inside `.com-content-article__body` on the home page did not animate, because the move to the `bsbasic-reveal` hook (see "Reveal hook" in project-notes) dropped the old catch-all for Bootstrap cards in content. `.com-content-article__body .card` is now a target in both `js/animate.js` (`CARDS`) and the pre-hide list in `scss/_animations.scss`. Cards elsewhere in component output (forms, login) are still not targets. Stagger, speed and on-load behaviour are the same as for other cards.

### Footer no longer animates (2026-11-12, branch feat/blog-item-animation)
The `<footer>` lost its `bsbasic-reveal bsbasic-reveal--section` classes in `index.php`, so it is never an animation target (the footer is a closing band, and fading it in read as noise). Animate help text in both language files and the project-notes lists updated. Entries above that name the footer as a section describe 1.4.0 as released.

### Fix: entrance animations on page load (2026-11-12, branch feat/blog-item-animation)
Targets already in view when the page loaded did not animate: `animate.js` hid them and revealed them in effectively the same frame, so there was no committed hidden state to transition from, and they were also visible for an instant before hiding. Now `index.php` puts `bsbasic-anim-pending` on `<html>` whenever Entrance Animation is set, and `scss/_animations.scss` hides the targets from the first paint (selectors mirror `animate.js`; skipped for the target kinds the Animate param excludes). `animate.js` adds its own hidden classes, removes the pending class in the same task (`release()`, called on every exit path, including reduced motion and no `IntersectionObserver`), forces a reflow and starts observing two animation frames later, so on-load targets animate with the chosen effect, speed and stagger like any other. If the script never runs, a `bsbasic-anim-failsafe` keyframe reveals everything after 2.5s. Only applies with `prefers-reduced-motion: no-preference`. Not yet checked live.

### Animation Speed slider; stagger scales with speed (2026-11-12, branch feat/blog-item-animation)
**Animation Speed** (`animSpeed`) is now a range slider, 200 to 2000 ms in steps of 50, default 600, replacing the Fast / Default / Slow list; `index.php` clamps it and emits `--bsbasic-anim-dur:<n>ms` only when it is not 600. Saved values `fast` / `default` / `slow` from 1.4.0 are not migrated (local dev only; they fall back to 600). Joomla's core range field (`layouts/joomla/form/field/range.php`) renders a bare `<input type="range">` with no readout, so the field uses a layout of its own: new `layouts/bsbasic/range-ms.php`, selected with `layout="bsbasic.range-ms"` and `layoutIncludePath="templates/puffermedia-bsbasic/layouts"` (Joomla resolves that path from the site root), and the new `layouts` folder is listed in the manifest `<files>`. The slider is 50% of its column (`w-50`) with the value, updated live while dragging (`oninput`), beside it. The label reads "Animation Speed (ms)". The stagger step now scales with the duration: `index.php` passes 2/15 of it (80ms at 600) as `data-bsbasic-anim-step` on `<html>` and `js/animate.js` reads it (falls back to 80); cap still 8 steps. Language files and project-notes updated. Not yet checked live.

### Appearance tab: Animation section (2026-11-11, branch feat/animations)
New **Animation** section under Appearance with five params. **Tile Hover Effect** (`animHover`: None / Lift / Zoom image / Lift and zoom image; default Lift, which matches the old hard-coded hover) styles article tiles (`.mod-articles-item`) and feed tiles (`.bsbasic-feed__tile`); `index.php` puts `bsbasic-hover-<value>` on `<body>` and the hover rules moved from `_cards.scss` and `_feed.scss` into the new `scss/_animations.scss`. **Entrance Animation** (`animEntrance`: None / Fade in / Slide up / Zoom in; default None) animates elements as they scroll into view. It only loads the new `js/animate.js` (asset `tpl.bsbasic.animate`) when set; `index.php` passes the settings as `data-bsbasic-anim*` attributes on `<html>`. Dependent params: **Animate** (`animTargets`: cards, tiles and sections / cards and tiles only / sections only; sections are banner, top-a, top-b, bottom and footer, and animate as one block so cards inside them do not animate separately), **Animation Speed** (`animSpeed`: .3s / .6s / 1s, emitted as `--bsbasic-anim-dur` only when not default) and **Stagger** (`animStagger`, default on; cards revealed in the same scroll step get an 80ms-per-card delay, capped at 8 steps). The script uses one `IntersectionObserver`, animates only `opacity` and `transform`, removes its classes after the transition so hover effects work again, and does nothing for visitors with `prefers-reduced-motion: reduce`. Elements that start in view may flash visible for a moment before hiding and animating, because the script runs after parsing. At default params the only output changes are the `bsbasic-hover-lift` body class and the `bsbasic-reveal` hook class below. Manifest and both language files updated. Not yet checked live.

**Fix (2026-11-12):** with Animate = cards and sections, bands that hold cards (top-a, top-b, bottom) animated as one block and skipped their cards, so bottom-a and bottom-b showed no tile animation. Now a band holding cards leaves the animating to its cards (staggered); bare bands (banner, footer) still animate as a block, and Sections only still animates every band. Descriptions in both language files updated.

**Reveal hook:** animation targets are marked in markup with `bsbasic-reveal` (cards and tiles: `chromes/card.php`, `mod_feed/tiles.php`) and `bsbasic-reveal bsbasic-reveal--section` (the five bands in `index.php`), so `animate.js` no longer carries per-position selector lists; only `.mod-articles-item` (core markup) stays a selector. Generic Bootstrap `.card` elements inside article content no longer animate. The plan for a pure-CSS version is in project-notes.md under "Animations (hover and entrance)".

New **Container Background Color** param (Appearance > Colors, blank default = no color). When set, `index.php` emits `--bsbasic-container-bg` and wraps `top-a`, `top-b`, `main`, `bottom-a` and `bottom-b` in one `div.bsbasic-main-inner` with the container class, so the color runs unbroken across all of them while Body Background Color shows around it (most visible with Layout Width: Boxed). The padding is the new **Container Padding** param (Layout > Content; None 0 / Default 1.5rem / Small 2.5rem / Large 5rem), emitted as `--bsbasic-container-pad` only when Container Background Color is set and the choice isn't Default (`_layout.scss` falls back to 1.5rem). ### Fix: bottom band shows the Container Background Color (2026-11-03, branch fix/minor-round-2)
`.bsbasic-bottom` kept its own surface-gray background inside the container box, so it read as a second color. It is now transparent when it is a direct child of `.bsbasic-main-inner` (`scss/_sections.scss`); its top rule stays. Without a container color the gray band is unchanged. Not yet checked live.

### Layout: bottom-a and bottom-b tile side by side (2026-11-03, branch fix/minor-round-2)
`bottom-a` and `bottom-b` were two separate full-width bands, so they always stacked. They now share one `div.bsbasic-bottom` band (surface background, top rule, indent) holding a Bootstrap `row g-4` with a `col-lg` column per populated position: two equal columns from lg up, full width when only one has modules, stacked below lg. The `bsbasic-bottom-a/-b` classes moved to the columns so `_cards.scss` still matches; `_sections.scss` and the indent rule in `_layout.scss` now target `.bsbasic-bottom`. The visible seam between the two old bands is gone. `top-a`/`top-b` are unchanged (still stacked). Not yet checked live.

### Fix: no content indent in Boxed layout (2026-11-03, branch fix/minor-round-2)
With Layout Width: Boxed, Content Indent (e.g. Small = 40px) pushed the header, breadcrumbs, articles, blog items and bottom/footer bands in from the box edge, so content looked offset to the right. `index.php` now emits `--bsbasic-indent:0` whenever the layout is Boxed, ignoring the Content Indent param there; Fluid is unchanged. The Content Indent field now has `showon="layoutWidth:fluid"`, so it is hidden in the editor while Layout Width is Boxed (its help text says so). No SCSS change. Not yet checked live.

### Fix: hamburger menu did nothing (2026-11-03, patch fix, checked live)
`index.php` registered `media/vendor/bootstrap/js/bootstrap.bundle.min.js`, which Joomla 6 does not ship (it has separate per-component files and registers them as assets such as `bootstrap.collapse`), so the file 404ed and the navbar toggler's `data-bs-toggle="collapse"` had no script behind it. The template now calls `$wa->useScript('bootstrap.collapse')` and no longer registers the bundle. The drop-down menu is CSS-only, so no other Bootstrap script is needed. **Second part, found once the menu opened:** Joomla 6's `mod_menu` renders a `button.mod-menu__toggle-sub` beside each parent link. The mobile rules in `scss/_header.scss` made parents block-level and hid the chevron but left the button, an empty box on its own line that broke the item list. Below the nav breakpoint the button is now hidden (submenus are always open there), except for heading/separator parents, where the button wraps the label. The stale "no toggle markup" comment was corrected. `template.css` rebuilt. Both parts checked live; remaining mobile gaps are listed in Known Issues.

## 1.0.0 (2026-11-01)

Initial release. The entries below run newest first down to the initial version.

### `.btn-secondary` follows the primary color (2026-11-01)
`.btn-secondary` was neutral grey at rest and only took the accent on hover. It now mirrors `.btn-primary` in `scss/_base.scss`: background and border use `--bsbasic-primary` (including disabled), hover and pressed use `--bsbasic-accent-dark`. `template.css` rebuilt; not yet checked live.

### Hide `role="tooltip"` text for logged-in editors (2026-11-01)
On a real-world test site, a user logged in on the frontend saw the literal text of Joomla's edit-icon tooltip (`<div role="tooltip" id="editarticle-N">`) printed on the page. Cassiopeia hides these in its own CSS (`[role=tooltip]:not(.show)` is `display:none`, shown on `:hover + ` / `:focus + `); this template had no equivalent. `scss/_content.scss` now carries the same rules, restyled with the template tokens, including the offsets for `editarticle-`, `editcontact-`, `id-skip-` and `cbunpublish` ids. `template.css` rebuilt; not yet checked live.

### Header search: input and button join as one pill (2026-11-01)
The header search field's pill radius ran into the Search button (Smart Search renders a Bootstrap `.input-group`). In `scss/_search.scss` the input now rounds only its start corners and the button only its end corners (longhand logical radii, beating Bootstrap's input-group corner rules), the group no longer wraps, and the button keeps its natural width. `template.css` rebuilt; not yet checked live.

### Gap beside floated article images (2026-11-01)
`.item-image.float-start` had no space between the image and the wrapped text. It now gets `margin-inline-end: 1.5rem` (and `.float-end` gets `margin-inline-start: 1.5rem`). Margin rather than padding, so the gap sits outside the figure. `scss/_content.scss`; `template.css` rebuilt; not yet checked live.

### Single-article body aligns with the content indent (2026-11-01)
Found on two test sites (one a sample-data page with a populated `sidebar-right`): the `.page-header` title took the left indent but the article body did not. Joomla puts the `.page-header` *inside* `.com-content-article.item-page`, so the indent now sits on that article element at 992px and wider, with or without sidebars, and a `.page-header` inside `.item-page` drops its own indent (no double indent). With no sidebars the article is left-aligned at the indent and its cap is `46rem + indent` so the text measure is unchanged; below 992px it stays centred. `scss/_content.scss`; `template.css` rebuilt; not yet checked live.

### Appearance and Advanced params, left indent, copyright default (2026-11-01)
All params keep their saved names; only labels changed. `template.css` rebuilt; not yet checked live. Blank Primary follows Accent, so existing styles look the same. **Header Color** and **Footer Color** gained a **Primary** option (`--primary` modifiers). A standalone Header Background Color field was tried and removed in favour of these dropdown options. (4) **Font colors**: Title Font Color (h1–h6, article h2–h4, blog titles), Header Font Color and Footer Font Color, each a CSS variable overridden inline only when set. ### Header menu spacing and drop-down caret (2026-10-29)
Core `mod_menu` gives links only their `anchor_css` class, not `.nav-link`, so the padding, underline and hover rules in `scss/_header.scss` never reached the real menu markup. Those rules now match `:is(.nav-link, .mod-menu a, .mod-menu__heading)`, and the item gap is `.25rem`. The drop-down indicator was missing because `span.icon-chevron-down` needs an icon font this template does not load; it is now a CSS-drawn caret on `.mod-menu__toggle-sub` (rotates when `aria-expanded`), pulled into the link's padding on desktop and hidden on mobile, where submenus are always open. `template.css` rebuilt; not yet checked live. Follow-up after a screenshot: the menu row wrapped (Bootstrap `.nav` allows it), links were underlined by the global link rule, and the negative margin on the caret made items uneven. Now `.mod-menu` is `nowrap` on desktop, menu links are `text-decoration:none; white-space:nowrap`, and a parent's link and toggle share the item's padding (link keeps `.15rem` on the right, the toggle supplies `.85rem`) instead of using a negative margin. Second follow-up: parent items sat ~5px lower than plain ones because only parents were flex rows; every top-level `li` is now `display:flex; align-items:center` and menu links are `display:block`, so all items share one baseline (mobile keeps `align-items:stretch`).

### Category blog layouts: columns, masonry, boxed (2026-10-28)
Comparing against Cassiopeia (on a site with Joomla sample data) showed Joomla emits `columns-N`, `masonry-N` and `boxed` on `.blog-items` but ships no CSS for them, so every blog rendered as one stacked list. `scss/_content.scss` now supports them. `columns-2/3/4` use a grid (`column-gap: 2rem`): four and three columns drop to two below 992px, and all collapse to one below 768px. `masonry-2/3/4` use CSS `column-count` with the same breakpoints and `break-inside: avoid`. `boxed` makes each item a bordered card (radius, small shadow, 3px accent top border, `1.5rem` content padding, `1.5rem` gap) with no bottom hairline. Image positions use Cassiopeia's class names, entered in the category's "Blog Class" field (Joomla itself emits none of them): `image-left` and `image-right` (image `40%` wide beside the content, `1.5rem` gap, stacked below 768px), `image-bottom`, and `image-alternate` combined with `image-left`, `image-right` or `image-top` (flips every odd item). Joomla's own Intro Image float (`float-start` / `float-end`) is untouched. `template.css` rebuilt; not yet checked live.

### Initial version (2026-10-22 to 2026-10-26)
The template's starting point, combined from the pre-release builds. Editorial styling on Joomla's bundled Bootstrap 5: serif headings, a light header, reading-width articles, refined cards, breadcrumbs and footer, and an accent color set through CSS variables (default `#ff0000`). Menus: desktop hover/focus drop-down panels and an indented mobile stack in `scss/_header.scss`, plus `html/mod_menu/default.php` (identical to core's) so the Layout picker offers a `puffermedia-bsbasic` entry; Cassiopeia's "Collapsible Dropdown" layout, which the picker also lists, renders a duplicated, invalid menu with this template. Modules: `html/layouts/chromes/card.php` adds the `card` chrome (Joomla core has none for site templates), the footer uses `style="html5"` instead of the invalid `xhtml`, and shared elevation tokens (`--bsbasic-shadow-sm` / `-md`) give the header and cards subtle shadows; footer module titles are small caps, with spacing between stacked modules. Also fixed a fatal 500 on every page in early builds: inside a template `$this` is the Document object, so `$this->document->getWebAssetManager()` and `$this->document->setMetaData()` became `$this->getWebAssetManager()` and `$this->setMetaData()`.
